# Accessibility Code Patterns

Practical, copy-paste-ready patterns for common accessibility requirements. Each pattern is self-contained and linked from the main [SKILL.md](../SKILL.md).

---

## Buttons

Use native `<button>` elements. Add `aria-label` when the visible label isn't descriptive enough.

```jsx
<button>Save changes</button>

{/* Icon-only button */}

<button aria-label="Close dialog">×</button>
```

---

## Links

Link text must be descriptive. Announce when a link opens in a new tab.

```jsx
<a href="/page">Descriptive link text</a>

{/* External link */}

<a href="https://external.com" target="_blank" rel="noopener">
  External site

  <span className="visually-hidden">(opens in new tab)</span>
</a>
```

---

## Navigation

Use `aria-label` to distinguish multiple `<nav>` landmarks. Mark the current page with `aria-current="page"`.

```jsx
<nav aria-label="Main">
  <ul>
    <li><a href="/" aria-current="page">Home</a></li>

    <li><a href="/about">About</a></li>
  </ul>
</nav>
```

## Modal structure

Pair with the [Modal focus trap](#modal-focus-trap) pattern for full keyboard support. Prefer the native `<dialog>` element (see below) over this manual markup when browser support allows — it handles focus trapping, `Escape`-to-close, and background inertness automatically.

```jsx
<div role="dialog" aria-modal="true" aria-labelledby="dialog-title">
  <h2 id="dialog-title">Confirm Action</h2>

  {/* content */}

  <button>Confirm</button>

  <button>Cancel</button>
</div>
```

## Modal focus trap

Trap keyboard focus inside a modal dialog so Tab/Shift+Tab cycle through its focusable elements and Escape closes it. Filter out disabled/hidden elements before computing the first/last focusable node, guard the case where nothing is focusable, remove the listener on close, and restore focus to the element that opened the modal.

```jsx
function useFocusTrap(modalRef, isOpen, onClose) {
  useEffect(() => {
    if (!isOpen) return undefined;

    const modal = modalRef.current;
    const previouslyFocused = document.activeElement;

    const getFocusable = () =>
      Array.from(
        modal.querySelectorAll(
          'button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])',
        ),
      ).filter((el) => !el.disabled && el.type !== "hidden");

    const handleKeyDown = (e) => {
      if (e.key === "Escape") {
        onClose();
        return;
      }

      if (e.key !== "Tab") return;

      const focusable = getFocusable();

      if (focusable.length === 0) {
        e.preventDefault(); // nothing focusable inside — keep focus trapped on the modal
        return;
      }

      const first = focusable[0];
      const last = focusable[focusable.length - 1];

      if (e.shiftKey && document.activeElement === first) {
        e.preventDefault();
        last.focus();
      } else if (!e.shiftKey && document.activeElement === last) {
        e.preventDefault();
        first.focus();
      }
    };

    modal.addEventListener("keydown", handleKeyDown);
    getFocusable()[0]?.focus();

    return () => {
      modal.removeEventListener("keydown", handleKeyDown);
      if (previouslyFocused instanceof HTMLElement) previouslyFocused.focus();
    };
  }, [isOpen, modalRef, onClose]);
}
```

The native `<dialog>` element (opened with `.showModal()`) handles focus trapping, `Escape`, and background inertness automatically — prefer it over a manual trap when browser support allows.

## Skip link

Allows keyboard users to bypass repetitive navigation and jump straight to main content.

```jsx
<>
  <a href="#main-content" className="skip-link">
    Skip to main content
  </a>

  <header>{/* navigation */}</header>

  <main id="main-content" tabIndex={-1}>
    {/* main content */}
  </main>
</>
```

```css
.skip-link {
  position: absolute;

  top: -40px;

  left: 0;

  background: #000;

  color: #fff;

  padding: 8px 16px;

  z-index: 100;
}

.skip-link:focus {
  top: 0;
}
```

## Error handling

Announce errors to screen readers and focus the first invalid field on submit. Put the live region on the error message itself, not on a wrapping element too — nesting an `aria-live="polite"` container around a `role="alert"` (implicitly `aria-live="assertive"`) child causes unreliable or doubled announcements. Render the error conditionally rather than leaving an empty `role="alert"` in the DOM on load — alerts announce on insertion/change, not on initial render.

```jsx
function EmailField() {
  const [error, setError] = useState("");

  const validate = (value) => {
    setError(
      /\S+@\S+\.\S+/.test(value)
        ? ""
        : "Please enter a valid email address (e.g., name@example.com)",
    );
  };

  return (
    <div className="field">
      <label htmlFor="email">Email</label>

      <input
        type="email"
        id="email"
        aria-invalid={Boolean(error)}
        aria-describedby={error ? "email-error" : undefined}
        onBlur={(e) => validate(e.target.value)}
      />

      {error && (
        <p id="email-error" className="error" role="alert">
          {error}
        </p>
      )}
    </div>
  );
}
```

```jsx
function handleSubmit(e) {
  e.preventDefault();

  const firstInvalid = e.currentTarget.querySelector('[aria-invalid="true"]');

  firstInvalid?.focus();
}
```

## Form labels

Every input needs an associated label—either explicit (`htmlFor`/`id`) or implicit (wrapping `<label>`).

```jsx
{/* ❌ No label association */}

<input type="email" placeholder="Email" />

{/* ✅ Explicit label */}

<label htmlFor="email">Email address</label>

<input
  type="email"
  id="email"
  name="email"
  autoComplete="email"
  required
/>

{/* ✅ Implicit label */}

<label>
  Email address

  <input type="email" name="email" autoComplete="email" required />
</label>

{/* ✅ With instructions */}

<label htmlFor="password">Password</label>

<input
  type="password"
  id="password"
  aria-describedby="password-requirements"
/>

<p id="password-requirements">
  Must be at least 8 characters with one number.
</p>
```

## Dragging movements

Any action triggered by dragging must offer a single-pointer alternative (WCAG 2.5.7).

```jsx
{/* ❌ Drag-only reorder */}

<ul className="sortable-list" draggable="true">
  <li>Item 1</li>

  <li>Item 2</li>
</ul>

{/* ✅ Drag + button alternatives */}

<ul className="sortable-list">
  <li>
    <span>Item 1</span>

    <button aria-label="Move Item 1 up" onClick={() => moveItem(0, -1)}>↑</button>

    <button aria-label="Move Item 1 down" onClick={() => moveItem(0, 1)}>↓</button>
  </li>

  <li>
    <span>Item 2</span>

    <button aria-label="Move Item 2 up" onClick={() => moveItem(1, -1)}>↑</button>

    <button aria-label="Move Item 2 down" onClick={() => moveItem(1, 1)}>↓</button>
  </li>
</ul>
```

Also applies to sliders, map panning, colour pickers, and similar drag-based widgets—always provide an equivalent click/tap or keyboard path.

## ARIA tabs

Tabs require `role="tablist"`, `role="tab"`, and `role="tabpanel"` with proper `aria-selected`, `aria-controls`, and keyboard support.

```jsx
function ProductTabs() {
  const [activeTab, setActiveTab] = useState("tab-1");

  return (
    <>
      <div role="tablist" aria-label="Product information">
        <button
          role="tab"
          id="tab-1"
          aria-selected={activeTab === "tab-1"}
          aria-controls="panel-1"
          tabIndex={activeTab === "tab-1" ? 0 : -1}
          onClick={() => setActiveTab("tab-1")}
        >
          Description
        </button>

        <button
          role="tab"
          id="tab-2"
          aria-selected={activeTab === "tab-2"}
          aria-controls="panel-2"
          tabIndex={activeTab === "tab-2" ? 0 : -1}
          onClick={() => setActiveTab("tab-2")}
        >
          Reviews
        </button>
      </div>

      <div role="tabpanel" id="panel-1" aria-labelledby="tab-1" hidden={activeTab !== "tab-1"}>
        {/* Panel content */}
      </div>

      <div role="tabpanel" id="panel-2" aria-labelledby="tab-2" hidden={activeTab !== "tab-2"}>
        {/* Panel content */}
      </div>
    </>
  );
}
```

Arrow keys should move focus between tabs; the active tab receives `tabIndex={0}` while inactive tabs use `tabIndex={-1}`.

## Live regions and notifications

Use `aria-live` to announce dynamic content changes to screen readers without moving focus.

```jsx
{/* Status updates (polite — waits for pause in speech) */}

<div aria-live="polite" aria-atomic="true" className="status">
  {/* Content updates announced to screen readers */}
</div>

{/* Urgent alerts (assertive — interrupts) */}

<div role="alert" aria-live="assertive">
  {/* Interrupts current announcement */}
</div>
```

```jsx
function useAnnouncer() {
  const politeRef = useRef(null);
  const assertiveRef = useRef(null);

  const announce = (message, type = "polite") => {
    const node = type === "assertive" ? assertiveRef.current : politeRef.current;

    node.textContent = "";

    requestAnimationFrame(() => {
      node.textContent = message;
    });
  };

  const Announcer = () => (
    <>
      <div ref={politeRef} aria-live="polite" aria-atomic="true" className="visually-hidden" />
      <div ref={assertiveRef} role="alert" aria-live="assertive" className="visually-hidden" />
    </>
  );

  return { announce, Announcer };
}
```

Clear the container before writing to ensure the same message triggers a new announcement.

## Screen reader commands

Quick reference for the most common screen reader shortcuts.

| Action | VoiceOver (Mac) | NVDA (Windows) |

| ------------- | ------------------- | -------------- |

| Start/Stop | ⌘ + F5 | Ctrl + Alt + N |

| Next item | VO + → | ↓ |

| Previous item | VO + ← | ↑ |

| Activate | VO + Space | Enter |

| Headings list | VO + U, then arrows | H / Shift + H |

| Links list | VO + U | K / Shift + K |
